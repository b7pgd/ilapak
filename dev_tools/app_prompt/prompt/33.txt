---

0. PS WEB — LINGKUNGAN KERJA

Saya menggunakan PS Web, yaitu browser-based source-code search engine dengan sintaks PowerShell-like.

PS Web BUKAN Windows PowerShell penuh.

Jangan mengasumsikan semua command, operator, parameter, atau syntax PowerShell tersedia.

Kemampuan PS Web ditentukan oleh Engine 1–4 di bawah.

Gunakan hanya kemampuan yang memang didukung.

Jangan pernah mengarang command atau flag baru.

Jika sebuah kebutuhan tidak didukung PS Web, jangan berpura-pura command tersebut tersedia. Gunakan kombinasi command yang memang didukung.

---

1. ARSITEKTUR PS WEB

PS Web terdiri dari beberapa layer:

engine.js
    ↓
engine1.js
    ↓
engine2.js
    ↓
engine3.js
    ↓
engine4.js

Secara konseptual:

Engine 1
Baseline / legacy execution
        ↓
Engine 2
Read / file-range compatibility
        ↓
Engine 3
Search compatibility
        ↓
Engine 4
Final command normalization / routing

Jangan mengasumsikan semua layer dipanggil dengan cara yang sama.

Jika perlu memahami execution flow PS Web, baca source Engine yang relevan terlebih dahulu dan gunakan API/registrasi yang benar-benar terlihat di source.

Jangan membuat asumsi arsitektur berdasarkan nama file saja.

---

2. KEMAMPUAN ENGINE 1–4

ENGINE 1 — BASELINE EXECUTION

Engine 1 menyediakan baseline / legacy command execution.

Engine 1 memiliki:

executeCommand(command)

Engine 1 juga menyediakan tokenizer dan parsing command yang digunakan oleh execution flow.

Jika debugging membutuhkan pemahaman tentang command execution, baca implementasi aktual Engine 1.

Jangan mengasumsikan Engine 1 memiliki command yang tidak terlihat di source.

---

ENGINE 2 — READ / FILE RANGE

Engine 2 menangani operasi pembacaan source dan range.

Command yang didukung:

Get-Content
cat
Select-Object
SelectObject

Kemampuan range yang tersedia mencakup pola seperti:

Get-Content <file> <start> <end>

dan:

Select-Object -Path <file> -Skip <N> -First <M>

Gunakan operasi ini untuk mengambil bagian file yang relevan tanpa membaca seluruh file jika tidak diperlukan.

Contoh generik:

Get-Content "path/to/file" 100 180

atau:

Select-Object -Path "path/to/file" -Skip 100 -First 80

Perhatikan bahwa "-Skip" mengikuti semantics source Engine 2 dan bukan asumsi dari tool lain.

---

ENGINE 3 — SEARCH

Engine 3 menangani pencarian source.

Command search yang tersedia:

grep
grep-batch
grep--batch
grep-b
Select-String
SelectString

Untuk batch search, gunakan:

grep-batch

Jangan mengarang variasi command seperti:

grep-all
grep-recursive
search-files
find-text
ripgrep
rg

kecuali command tersebut memang ditemukan di source PS Web.

---

4. REGEX PS WEB

PS Web mendukung regex melalui Engine 3.

Contoh generik:

grep-batch -regex "function\(.*\)"

atau:

Select-String -Pattern "api/.*scanner" -regex

PENTING:

Backslash regex harus dipertahankan.

Pattern:

\(
\)
\.
\[
\]
\s
\d

harus tetap diterima sebagai regex.

Jangan menghapus backslash dari pattern.

Jangan mengubah regex menjadi literal hanya karena syntax terlihat seperti escape sequence.

Jika regex tidak diperlukan, gunakan literal search terlebih dahulu.

Prioritas:

literal search
↓
regex jika memang diperlukan

---

5. BATCH SEARCH

Gunakan "grep-batch" jika beberapa pattern memang perlu dicari dalam satu tahap.

Format harus mengikuti kemampuan PS Web yang nyata.

Contoh generik:

grep-batch "pattern-one" "pattern-two" "pattern-three"

Jika membutuhkan regex:

grep-batch -regex "pattern-one\(.*\)" "pattern-two\."

Jangan mengarang syntax batch baru.

Jika tidak yakin terhadap syntax tertentu, baca implementasi Engine 3 terlebih dahulu daripada menebak.

---

6. PS WEB VS HOST POWERSHELL

Bedakan dua hal:

A. Command yang diberikan ke PS Web

Contoh:

Get-Content
Select-Object
grep-batch
Select-String

Harus mengikuti kemampuan Engine 1–4.

B. PowerShell host yang dijalankan user untuk mengambil output dari filesystem

Contoh:

Get-ChildItem
Get-Content
Select-String
Where-Object
Select-Object
Test-Path

Untuk batch investigasi filesystem yang dijalankan di Windows, gunakan PowerShell.

Jangan mencampurkan syntax PS Web dengan syntax PowerShell host secara sembarangan.

Jika saya meminta batch untuk dijalankan di PS Web, gunakan command PS Web.

Jika saya meminta batch Windows untuk mengumpulkan source dari filesystem, gunakan PowerShell host.

8. BACA KONTEKS TERLEBIH DAHULU

Baca seluruh percakapan dan gunakan hasil investigasi sebelumnya.

Pahami:

- bug / fitur yang diminta
- expected behavior
- actual behavior
- file yang disebut user
- function / component yang sudah diketahui
- route yang sudah diketahui
- flow yang sudah ditemukan
- constraint user
- hasil search sebelumnya

Jangan mengulang search yang sudah dilakukan tanpa alasan.

Jika source yang sudah tersedia cukup untuk memastikan root cause:

STOP SEARCH → LANGSUNG FIX.

Jangan melakukan investigasi tambahan hanya untuk terlihat lebih lengkap.

10. JANGAN MENGGUNAKAN USE CASE LAMA SEBAGAI TEMPLATE

Setiap bug baru harus diperlakukan berdasarkan konteks aktualnya.

Hasil investigasi sebelumnya hanya digunakan jika memang relevan dengan masalah saat ini.

Jangan menjadikan kasus debug sebelumnya sebagai contoh atau asumsi root cause.

Gunakan Engine 1–4 sebagai spesifikasi kemampuan PS Web, bukan sebagai template isi masalah.

12. JANGAN SCAN ROOT PROJECT SECARA BLIND

Dilarang menjadikan ini sebagai default:

Get-ChildItem -Recurse -File

dari root project lalu melakukan search terhadap semuanya.

Jika recursive search memang diperlukan, tentukan folder target terlebih dahulu.

Contoh generik:

$files = Get-ChildItem "D:\project\frontend\app" -Recurse -File |
    Where-Object {
        $_.Extension -in '.tsx','.ts','.js','.jsx'
    }

Atau:

$files = Get-ChildItem "D:\project\backend" -Recurse -File -Filter *.go

Jangan membuat "$files" dari seluruh project jika hanya membutuhkan satu area.

14. SEARCH BERTAHAP

Gunakan progressive targeted search.

LEVEL 1 — SOURCE YANG DISEBUT USER

Jika user memberikan file spesifik, mulai dari file tersebut.

Jika user memberikan function, mulai dari function tersebut.

Jika user memberikan route, mulai dari handler route tersebut.

Jika user memberikan error tertentu, cari lokasi error tersebut terlebih dahulu.

---

LEVEL 2 — TRACE SOURCE YANG DITEMUKAN

Setelah membaca source, identifikasi dependency nyata.

Contoh konseptual:

component
↓
function
↓
dependency
↓
API

Jika source menunjukkan dependency tertentu, baru trace dependency tersebut.

Jangan mencari semua keyword yang berhubungan secara semantik.

---

LEVEL 3 — CROSS-FILE SEARCH

Jika source menunjukkan file lain:

file A
↓
import / call
↓
file B

baru baca/search file B.

Jika source menunjukkan endpoint:

fetch("/api/example")

baru cari handler "/api/example".

Jika handler menunjukkan service tertentu, baru trace service tersebut.

Setiap pencarian harus memiliki alasan yang berasal dari source sebelumnya.

16. OUTPUT HARUS HEMAT DAN TERARAH

Tujuan search adalah mendapatkan informasi yang dibutuhkan, bukan membuang seluruh source ke chat.

Hasil harus jelas:

FILE → BARIS → KODE

Gunakan:

Select-Object Path,LineNumber,Line

atau:

"$($_.Path):$($_.LineNumber) >>> $($_.Line.Trim())"

Gunakan header:

===== NAMA INVESTIGASI =====

Batasi hasil jika terlalu luas:

Select-Object -First 20

Jika search menghasilkan terlalu banyak hasil:

persempit pattern atau folder pada batch berikutnya.

Jangan meminta user mengirim seluruh output noise.

18. TARGETED CONTEXT

Jika search menemukan lokasi tertentu tetapi membutuhkan context tambahan, ambil hanya block tersebut.

Contoh host PowerShell:

    Select-Object -Skip 140 -First 80

Atau gunakan kemampuan range Engine 2 jika investigasi dilakukan langsung melalui PS Web.

Jika sudah tahu function, ambil function tersebut dan sedikit context di sekitarnya.

Jangan meminta seluruh file jika hanya membutuhkan satu function/block.

24. ZERO MATCHES BUKAN OTOMATIS ENGINE BUG

Jika search menghasilkan:

No matches found.

jangan langsung menyimpulkan PS Web rusak.

Pertimbangkan terlebih dahulu:

pattern salah
↓
identifier berbeda
↓
file target salah
↓
path salah
↓
command syntax salah
↓
pattern terlalu spesifik
↓
source memang tidak mengandung string tersebut
↓
baru kemungkinan masalah search engine

Jika perlu menentukan apakah PS Web bermasalah, lakukan uji minimal yang terisolasi terhadap kemampuan yang dicurigai.

Jangan mengubah Engine 1–4 hanya karena sebuah search tidak menemukan source.

25. JANGAN MENGINVENT COMMAND PS WEB

Sebelum menggunakan command atau flag:

2. Pastikan syntax sesuai implementasi aktual.
3. Jangan mengimpor syntax dari:
   - PowerShell penuh
   - GNU grep
   - ripgrep
   - Bash
   - tool search lain.

Jika command tidak diketahui:

INSPEKSI ENGINE TERKAIT TERLEBIH DAHULU.

Jangan menebak.

---

26. REGEX HANYA JIKA DIPERLUKAN

Gunakan:

literal

terlebih dahulu jika cukup.

Gunakan regex jika memang membutuhkan:

- escaping
- alternatif
- wildcard
- grouping
- pola dinamis

Jika menggunakan regex, pertahankan backslash.

Contoh generik:

"foo\(bar\)"

bukan pattern yang kehilangan:

\

Jika regex menghasilkan error, periksa:

1. pattern asli
2. tokenizer
3. parsing argument
4. regex construction

Jangan langsung mengubah pattern menjadi literal jika user memang membutuhkan regex.
