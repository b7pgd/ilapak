1. BACA KONTEKS TERLEBIH DAHULU

Baca seluruh percakapan dan gunakan hasil investigasi sebelumnya.

Pahami:

bug / fitur yang diminta

expected behavior

actual behavior

file yang disebut user

function / component yang sudah diketahui

route yang sudah diketahui

flow yang sudah ditemukan

constraint user

hasil search sebelumnya


Jangan mengulang search yang sudah dilakukan tanpa alasan.

Jika source yang sudah tersedia cukup untuk memastikan root cause:

STOP SEARCH → LANGSUNG FIX.

2. PRINSIP UTAMA: SEARCH DARI YANG PALING DEKAT

Search harus mengikuti prinsip:

BUG
↓
FILE YANG DISEBUT USER
↓
FUNCTION / COMPONENT TERKAIT
↓
CALLER / CONSUMER
↓
ROUTE / API / BACKEND
↓
DEPENDENCY BERIKUTNYA JIKA MEMANG TERBUKTI DIPERLUKAN

Jangan membalik urutan menjadi:

BUG
↓
SCAN SELURUH PROJECT
↓
RIBUAN HASIL
↓
CARI-CARI YANG RELEVAN

Contoh

User mengatakan:

B7_label/frontend/app/scanner/page.tsx
fitur scan tidak bekerja dan kamera tidak terbuka.

Search pertama WAJIB fokus ke scanner/page.tsx.

Jangan langsung:

scan seluruh project

scan seluruh backend

scan seluruh frontend

scan dependency

mencari semua kata scanner

mencari semua route

mencari semua API


Pertama pahami file Scanner.

4. JANGAN PERNAH SCAN ROOT PROJECT SECARA BLIND

Dilarang menjadikan ini sebagai default:

rg -n 'scanner|camera|route|fetch|api|window|error' .

terhadap seluruh project.

Jangan melakukan:

root project
↓
semua folder
↓
semua file
↓
semua keyword

Search harus dimulai dari lokasi paling dekat.

Jika user memberikan:

frontend/app/scanner/page.tsx

maka gunakan:

rg -n -i 'Html5Qrcode|start\(|stop\(|camera|navigator\.mediaDevices|permission|useEffect' \
frontend/app/scanner/page.tsx

Bukan:

rg -n 'scanner|camera' .

5. EXCLUDE WAJIB

Jangan pernah membaca atau search:

node_modules
.next
.next-scanner
.git
dist
build
out
coverage
vendor
cache
temp
generated

Gunakan exclusion ketika melakukan recursive search.

Contoh:

rg -n -i 'pattern' . \
  -g '!node_modules/**' \
  -g '!.next/**' \
  -g '!.next-scanner/**' \
  -g '!.git/**' \
  -g '!dist/**' \
  -g '!build/**' \
  -g '!out/**' \
  -g '!coverage/**' \
  -g '!vendor/**' \
  -g '!cache/**' \
  -g '!temp/**' \
  -g '!generated/**'

Jika memungkinkan, lebih baik membatasi folder target daripada melakukan recursive search dari root.

Contoh:

rg -n 'ScannerHandler|/api/scanner' backend/

lebih baik daripada:

rg -n 'ScannerHandler|/api/scanner' .

7. SEARCH BERTAHAP, BUKAN SEARCH GABUNGAN SEJAK AWAL

Gunakan progressive targeted search.

LEVEL 1 — SOURCE YANG DISEBUT USER

Jika user memberikan:

frontend/app/scanner/page.tsx

mulai dari file tersebut.

Jika user memberikan:

handleScan()

mulai dari function tersebut.

Jika user memberikan:

/api/login

mulai dari route tersebut.


---

LEVEL 2 — TRACE SOURCE YANG DITEMUKAN

Setelah membaca file, identifikasi dependency nyata.

Contoh:

scanner/page.tsx
↓
startScanner()
↓
html5-qrcode
↓
camera initialization

Kalau source menunjukkan:

startScanner()
↓
fetch("/api/scanner")

baru cari /api/scanner.

Bukan mencari semua kata scanner di project.


---

LEVEL 3 — CROSS-FILE SEARCH

Jika source menunjukkan:

page.tsx
↓
scanner.ts

baru cari / baca:

scanner.ts

Jika source menunjukkan:

fetch("/api/scanner")

baru cari handler:

/api/scanner

Jika handler menunjukkan:

ScannerService

baru trace service tersebut.

Setiap pencarian harus memiliki alasan yang berasal dari source sebelumnya.

9. OUTPUT HARUS HEMAT DAN TERARAH

Tujuan search adalah mendapatkan informasi yang dibutuhkan, bukan membuang seluruh source ke chat.

Output harus jelas:

FILE:LINE:CODE

rg -n sudah memberikan format:

file:line:code

Gunakan header:

echo "===== SCANNER CAMERA LOGIC ====="

Jika search berpotensi menghasilkan banyak hasil, batasi:

rg -n -i 'pattern' file.tsx | head -20

Jangan menghasilkan ratusan / ribuan hasil jika beberapa baris sudah cukup.

Jika output terlalu banyak:

persempit pattern atau folder pada batch berikutnya.

Jangan meminta user mengirim seluruh output noise.

11. TARGETED CONTEXT

Jika rg menemukan lokasi tertentu tetapi membutuhkan context tambahan, ambil hanya block tersebut.

Contoh:

ambil function tersebut dan sedikit context di sekitarnya.

Jangan meminta seluruh file jika hanya membutuhkan satu function/block.

12. JIKA FILE YANG DIBERIKAN SUDAH CUKUP → LANGSUNG FIX

Jika user mengatakan:

frontend/app/scanner/page.tsx

Jangan mencari backend hanya karena "mungkin ada hubungannya".

Langsung fix.

Format:

KETEMU

<singkat>

FIX:

FILE: <path>
Bagian: <function/component>

Ubah menjadi:
<kode>

<command / langkah test>


---

13. JIKA BELUM CUKUP → SEARCH BERIKUTNYA HARUS BERDASARKAN TEMUAN

Jangan menebak.

Format:

Belum cukup konteks.

Dari source ditemukan:
<temuan singkat>

Yang perlu ditemukan:
<informasi spesifik>

Jalankan:
<1 batch Termux + rg>

Search berikutnya WAJIB menjelaskan hubungan dengan hasil sebelumnya.

Contoh:

scanner/page.tsx memanggil `/api/scanner`,
tetapi handler `/api/scanner` belum terlihat.

Saya perlu melihat handler tersebut.

Lalu:

echo "===== API SCANNER HANDLER ====="

rg -n -i \
'/api/scanner|ScannerHandler' \
backend/ | head -20

Bukan kembali melakukan:

rg -n 'scanner' .
