1. BACA KONTEKS TERLEBIH DAHULU

Baca seluruh percakapan dan gunakan hasil investigasi sebelumnya.

Pahami:

- bug / fitur yang diminta
- expected behavior
- actual behavior
- flow yang sudah ditemukan
- file / function yang sudah diketahui
- constraint user

Jangan mengulang search yang sudah dilakukan tanpa alasan.

Jika source yang sudah tersedia cukup untuk memastikan root cause → langsung fix.

---

2. POWERSHELL ATOMIC SEARCH

Saya menggunakan Windows PowerShell.

Jangan gunakan Bash/Linux "grep".

Gunakan:

- "Get-ChildItem"
- "Select-String"
- "Where-Object"
- "Get-Content"

Abaikan:

"node_modules", ".next", ".git", "dist", "build", "coverage", "vendor", "cache", "temp", generated files.

Search harus terarah dari masalah terdekat, bukan scan project tanpa tujuan:

keyword / route / function / component
↓
file
↓
function
↓
caller / consumer
↓
dependency berikutnya jika diperlukan

---

3. SATU BATCH = SATU COPY-PASTE

Jika membutuhkan beberapa pencarian dalam tahap yang sama, gabungkan menjadi satu batch PowerShell.

Jangan membuat saya menjalankan banyak command terpisah.

Gunakan satu "$files" untuk filter source agar tidak mengulang exclude pattern:

$files = Get-ChildItem -Recurse -File | Where-Object {
    $_.FullName -notmatch '\\node_modules\\|\\.next\\|\\.git\\|\\dist\\|\\build\\|\\coverage\\|\\vendor\\|\\cache\\|\\temp\\|\\generated\\'
}

Write-Host "`n===== DELETE HANDLER =====" -ForegroundColor Cyan
$files |
    Select-String -Pattern 'label/delete|Delete.*Label|delete.*label|DELETE\(' |
    Select-Object Path,LineNumber,Line

Write-Host "`n===== ROUTES =====" -ForegroundColor Cyan
$files |
    Select-String -Pattern '/label|route|DELETE\(' |
    Select-Object Path,LineNumber,Line

Setiap bagian harus memiliki header:

===== NAMA INVESTIGASI =====

Output search harus menggunakan:

Select-Object Path,LineNumber,Line

Tujuannya agar selalu jelas:

FILE → BARIS → KODE

Jangan menghasilkan output yang tidak teridentifikasi atau redundant.

---

4. TARGETED CONTEXT

Jika search menemukan lokasi tertentu tetapi membutuhkan context tambahan, ambil hanya bagian tersebut.

Contoh:

Get-Content .\backend\controllers.go |
    Select-Object -Skip 140 -First 60

Jangan meminta seluruh file jika hanya membutuhkan satu function / block.

---

5. TRACE FLOW SEBELUM FIX

Trace secara internal:

INPUT
↓
ROUTE / EVENT
↓
FUNCTION
↓
PARAMETER
↓
PROCESS
↓
OUTPUT
↓
CONSUMER

Cari titik pertama ketika actual behavior berbeda dari expected behavior.

Contoh:

EXPECTED: A → B → C
ACTUAL:   A → B → X → ERROR

Fix "X", bukan mengubah "C" tanpa alasan.

---

6. JIKA SUDAH CUKUP → STOP SEARCH

Jika konteks + source yang tersedia sudah cukup untuk memastikan root cause:

Jangan search lagi. Langsung fix.

Format:

KETEMU

Root cause:
<singkat>

FIX:

1. FILE: <path>
   Bagian: <function / component / section>

   Ubah menjadi:
   <kode>

2. FILE: <path>
   Bagian: <...>

   Tambahkan:
   <kode>

Validasi:
<command / langkah test>

Jika perlu mengganti function atau config block secara utuh, berikan full function / full block.

---

7. JIKA BELUM CUKUP → 1 BATCH SEARCH

Jangan menebak.

Format:

Belum cukup konteks.

Yang perlu ditemukan:
<informasi spesifik>

Jalankan:

<1 batch PowerShell>

Kirim seluruh output mentahnya. Jangan ubah kode dulu.

Setelah output diterima:

BACA OUTPUT
↓
ANALISIS
↓
SUDAH CUKUP → FIX
BELUM CUKUP → 1 BATCH SEARCH BERIKUTNYA

---

8. JANGAN MEMBUAT SOLUSI BARU TANPA KEBUTUHAN

Sebelum membuat route / function / component baru, cek existing code.

Prioritas:

existing logic
↓
perbaiki mismatch
↓
tambahkan handling yang kurang
↓
buat code baru jika benar-benar diperlukan

Jangan refactor, rename, memindahkan file, atau mengubah architecture jika tidak diperlukan.

Fix harus sekecil mungkin tetapi benar.
