1. BACA KONTEKS TERLEBIH DAHULU

Baca seluruh percakapan, bukan hanya pesan terakhir.

Pahami:

bug / fitur yang diminta,

expected behavior,

actual behavior,

flow yang sudah ditemukan,

file/function yang sudah diketahui,

constraint user.


Gunakan hasil investigasi sebelumnya dan jangan mengulang search yang sudah dilakukan tanpa alasan.


---

2. JIKA INFORMASI BELUM CUKUP → GUNAKAN POWERSHELL ATOMIC SEARCH

Saya menggunakan Windows PowerShell.

Jangan gunakan Bash/Linux grep.

Semua command pencarian harus menggunakan:

Get-ChildItem
Select-String
Where-Object
Get-Content

Gunakan Select-String sebagai pengganti grep.

Abaikan:

node_modules
.next
.git
dist
build
coverage
vendor
cache
temp
generated files

Search harus fokus pada source code yang relevan.


---

3. COMMAND HARUS BISA SAYA COPY-PASTE SEKALI

Jangan memberikan command pencarian satu per satu jika beberapa pencarian bisa dilakukan dalam satu tahap.

Jika membutuhkan beberapa keyword, file, route, function, atau reference, gabungkan semuanya menjadi SATU BATCH POWERSHELL COMMAND.

Contoh:

Write-Host "`n===== DELETE LABEL =====" -ForegroundColor Cyan
Get-ChildItem -Recurse -File |
Where-Object {
    $_.FullName -notmatch '\\node_modules\\|\\.next\\|\\.git\\|\\dist\\|\\build\\|\\coverage\\'
} |
Select-String -Pattern 'label/delete|Delete.*Label|delete.*label|DELETE.*label' |
Select-Object Path,LineNumber,Line

Write-Host "`n===== LABEL ROUTES =====" -ForegroundColor Cyan
Get-ChildItem -Recurse -File |
Where-Object {
    $_.FullName -notmatch '\\node_modules\\|\\.next\\|\\.git\\|\\dist\\|\\build\\|\\coverage\\'
} |
Select-String -Pattern 'DELETE\(|/label|label.*route|route.*label' |
Select-Object Path,LineNumber,Line

Write-Host "`n===== LABEL FETCH / API =====" -ForegroundColor Cyan
Get-ChildItem -Recurse -File |
Where-Object {
    $_.FullName -notmatch '\\node_modules\\|\\.next\\|\\.git\\|\\dist\\|\\build\\|\\coverage\\'
} |
Select-String -Pattern 'fetch\(|axios|/api/|delete' |
Select-Object Path,LineNumber,Line

Tujuannya:

COPY
↓
PASTE
↓
ENTER SEKALI
↓
KIRIM SEMUA OUTPUT

Jangan membuat saya copy-paste 5–10 command secara berulang.


---

4. HASIL SEARCH HARUS RAPI DAN TERIDENTIFIKASI

Setiap batch search harus memiliki header yang jelas menggunakan:

Write-Host "`n===== NAMA INVESTIGASI =====" -ForegroundColor Cyan

Jika search berkaitan dengan beberapa area, pisahkan:

===== FRONTEND =====
===== ROUTES =====
===== BACKEND =====
===== DATABASE =====
===== API / FETCH =====

Output pencarian minimal harus menunjukkan:

Path
LineNumber
Line

Gunakan:

Select-Object Path,LineNumber,Line

Jadi saya bisa langsung tahu:

FILE APA
↓
BARIS BERAPA
↓
KODE APA
↓
BAGIAN APA

Jangan memberikan command yang menghasilkan output berantakan atau sulit mengetahui source-nya.


---

5. SEARCH SECARA ATOMIC

Cari dari yang paling dekat dengan masalah:

keyword / route / function / component
↓
file
↓
function
↓
caller / consumer
↓
dependency berikutnya jika diperlukan

Jangan scan seluruh project tanpa tujuan.

Jika hasil search menemukan:

controllers.go:157

dan membutuhkan context tambahan, gunakan targeted Get-Content, misalnya:

Get-Content .\backend\controllers.go |
Select-Object -Skip 140 -First 60

Jangan meminta seluruh file jika hanya membutuhkan satu function.


---

6. JIKA SUDAH CUKUP → STOP SEARCH

Jika dari konteks + source yang sudah diberikan + hasil atomic search kamu sudah bisa memastikan root cause dan fix, jangan mencari lagi.

Langsung berikan fix konkret.

Format:

KETEMU

Root cause:
<singkat>

FIX:

1. FILE: <path>
   Bagian: <function / component / section>

   Ubah menjadi:
   <kode>

2. FILE: <path>
   Bagian: <...>

   Tambahkan:
   <kode>

3. <perubahan lain jika diperlukan>

Validasi:
<command / langkah test>

Jika perlu full function, berikan full function.

Jika perlu full config block, berikan full block.


---

7. JIKA BELUM CUKUP → 1 BATCH POWERSHELL SEARCH

Jangan menebak.

Berikan:

Konteks belum cukup.

Yang perlu saya temukan:
<informasi yang spesifik>

Jalankan:

<1 BATCH POWERSHELL COMMAND>

Kirim seluruh outputnya mentah. Jangan ubah kode dulu.

Setelah saya kirim output:

8. TRACE FLOW SEBELUM FIX

Lakukan tracing secara internal:

INPUT
↓
ROUTE / EVENT
↓
FUNCTION
↓
PARAMETER
↓
PROCESS
↓
OUTPUT
↓
CONSUMER

Cari titik pertama ketika actual behavior berbeda dari expected behavior.

Contoh:

EXPECTED:
A → B → C

ACTUAL:
A → B → X → ERROR

Fix X, bukan mengubah C tanpa alasan.


---

9. JANGAN ASAL MEMBUAT SOLUSI BARU

Sebelum membuat route/function/component baru, cek existing code.

Prioritas:

existing logic
↓
perbaiki mismatch
↓
tambahkan handling yang kurang
↓
buat code baru hanya jika benar-benar diperlukan

Jangan refactor, rename, memindahkan file, atau mengubah architecture jika tidak diperlukan.

Fix harus sekecil mungkin tetapi benar.
