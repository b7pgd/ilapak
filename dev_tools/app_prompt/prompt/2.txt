GOAL

Output ini akan digunakan sebagai konteks permanen AI.
Pada tahap implementasi, AI akan memecah konteks menjadi 3 lapisan (Global Architecture, Global UI/UX, dan Local File Contract) untuk efisiensi token.

Saat membangun frontend (misalnya generate index.html), AI akan menerima gabungan:
project.map (Global Architecture)
+
ui.map (Global UI/UX)
+
index.skeleton (Local File Contract)
↓
Generate index.html (AI sekarang tahu arsitektur, kontrak file, dan kontrak UI sehingga tampilan tidak berubah-ubah sendiri).

Saat membangun backend (misalnya generate main.go), AI hanya akan menerima:
project.map
+
main.skeleton
↓
Generate main.go (Tidak perlu ui.map, sehingga sangat hemat token untuk file backend).

Karena itu:
project.map HARUS cukup lengkap sehingga AI tidak perlu membaca skeleton file lain.
ui.map HARUS mengunci seluruh visual agar tidak diinterpretasikan bebas oleh AI.
Setiap skeleton HARUS hanya menjelaskan satu file.

TESTING_MAP (Struktur pengujian dan lokasi penempatan file test)
PERFORMANCE_CONTRACT (Aturan performa seperti lazy loading, pagination, debounce, cache policy, dan batas ukuran upload)

UI.MAP RESPONSIBILITY

ui.map bertugas menjelaskan kontrak visual global (Desain Antarmuka) agar AI tidak bebas menginterpretasikan layout, gaya, atau elemen frontend secara liar.
WAJIB berisi:
THEME (Gaya global seperti Dark/Light, Warna Primary, Radius, Shadow, Spacing, Typography)
LAYOUT (Struktur makro antarmuka seperti Header, Sidebar, Editor, Preview, dll)
COMPONENT REGISTRY (Daftar komponen visual universal seperti Toolbar, Card, Modal, Toast)
COMPONENT CONTRACT (Kontrak spesifik untuk elemen UI seperti varian, icon, posisi, urutan button, gap, atau perilaku responsifnya)
DESIGN_SYSTEM (Spesifikasi token visual mendalam seperti COLOR, TYPOGRAPHY, SPACING, RADIUS, ICON_SET, MOTION, BREAKPOINT, Z_INDEX)
INTERACTION (Kontrak alur UX/perilaku elemen visual saat berinteraksi, misal: Save -> Loading -> Disabled -> Toast Success)
NAMING (Standar konvensi penamaan komponen, fungsi, konstanta, variabel, route, endpoint, folder, database table, event, storage key, dan file CSS)

JANGAN menjelaskan kode HTML secara mentah, melainkan fokus pada kontrak tampilan.

DSL FORMAT

Gunakan format DSL.
Contoh untuk project.map / file.skeleton:
FILE{
NAME=handler.js
ROLE=Explorer
IMPORT{
api.js
state.js
}
EXPORT{
loadFolder
saveFile
}
FUNCTION{
loadFolder{
LINE=40-90
IN=path
OUT=TreeNode[]
BY{
init
}
CALL{
scanFolder
renderTree
}
TYPE=SIDE_EFFECT
}
}
}

MODULE{
Explorer{
OWNER=handler.js
PUBLIC{ loadFolder, openFile }
PRIVATE{ scanFolder, sortFiles }
DEPEND_ON{ api.js, state.js }
}
}

OWNERSHIP{
TreeNode -> handler.js
EditorState -> editor.js
HistoryLog -> history.go
}

DECISION_LOG{
D001{ Decision=Single HTML Architecture | Reason=Reduce deployment complexity }
D002{ Decision=SQLite | Reason=Local first }
}

Contoh untuk ui.map:
UI{
THEME{
Dark
Primary=#111
Radius=12
Shadow=Soft
Spacing=8
Typography=Inter
}
DESIGN_SYSTEM{
COLOR{ Primary=#111 | Background=#FFF }
ICON_SET=Lucide
BREAKPOINT{ Mobile=320px | Desktop=1024px }
}
INTERACTION{
Save{ Click -> Loading -> DisableButton -> ToastSuccess }
Delete{ Click -> ConfirmModal -> Refresh }
}
NAMING{
Component=PascalCase
Function=camelCase
Constant=UPPER_SNAKE
Private=camelCase
Route=kebab-case
Endpoint=snake_case
DatabaseTable=snake_case
CSS=kebab-case
}
BUTTON{
Save
variant=primary
icon=save
position=top-right
}
LAYOUT{
Header
Sidebar
Editor
Preview
}
COMPONENT{
Toolbar
Card
Modal
Toast
}
}
